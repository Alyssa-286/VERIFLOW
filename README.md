# VERIFLOW

**Beyond Aggregate Verifier Quality: Does Error-Mode Heterogeneity Predict RLVR Failure?**
A pre-registered, exactly rate-matched study of verifier false-positive structure in reinforcement learning with verifiable rewards (RLVR).

- **Paper:** [paper/main.pdf](paper/main.pdf) (source `paper/main.tex`; every number generated by `paper/make_numbers.py`)
- **Pre-registration:** https://osf.io/bs3wq/, DOI [10.17605/OSF.IO/BS3WQ](https://doi.org/10.17605/OSF.IO/BS3WQ); frozen text at tag `prereg-v1`; [addendum 1](docs/PREREG_ADDENDUM_1.md)
- **OSF project:** https://osf.io/w8scx/
- **Decision log (D0–D34):** [docs/DECISIONS.md](docs/DECISIONS.md) · **Phase ledger:** [docs/PHASE_LEDGER.md](docs/PHASE_LEDGER.md) · **Reproduce:** [docs/REPRODUCE.md](docs/REPRODUCE.md) · **Provenance and commit map:** [docs/PROVENANCE.md](docs/PROVENANCE.md)

## Question and answer

Among programmatic verifiers matched exactly on the base-weighted aggregate false-acceptance rate (F̄ = 0.3) and the true-positive rate (τ = 0.9), does the dispersion V of the per-error-mode false-acceptance probabilities predict the accuracy GRPO reaches, beyond the worst-mode rate f_max?

**Setting:** Qwen2.5-0.5B-Instruct, five-digit addition, four outcome-defined error modes, 100 GRPO steps, 48 verifier configurations × 2 seeds (96 runs, all valid).

**Registered estimates** (declared in advance as estimation with CIs, because power was < 0.5):

| Quantity | Estimate | 95 % CI |
|---|---|---|
| H1 b_V (matched arm, HC3) | −6.01 | [−7.59, −4.43] |
| H2 MSE{f_max, V} − MSE{f_max}, 13 held-out configs | −0.023 | [−0.047, −0.002] |
| H3 MSE{CGF} − MSE{f_max, V} | +0.002 | [−0.007, 0.011] |

At matched aggregate rates, higher dispersion went with lower accuracy, and V predicted outcomes better than the aggregate rate or f_max. **Caveats** (all in the paper): the registered grid contains duplicated verifier configurations (25 distinct of 36 matched; deduplicated b_V = −5.63 [−8.30, −2.95]), which weakens the registered held-out test; mechanism and aggregate-vs-dispersion analyses are post hoc and labelled exploratory; one small model, one task, a short horizon, two seeds per configuration. The Phase 4 census stability criterion is reported with its limitation ([docs/PHASE4_CLOSURE.md](docs/PHASE4_CLOSURE.md)); no claim is made about Qwen2.5-1.5B.

## Quick start (CPU)

```bash
uv sync
uv run pytest                                   # full test suite
uv run python -m experiments.analyse_grid --runs-root results/grid/run_records   # needs the verifier-log archive, see REPRODUCE
uv run python paper/make_numbers.py && (cd paper && pdflatex main && bibtex main && pdflatex main && pdflatex main)
```

See [docs/REPRODUCE.md](docs/REPRODUCE.md) for the full CPU and GPU reproduction, including the verifier-log release archive and the Slurm commands.

## Layout

| Path | Contents |
|---|---|
| `verifiers/` | every verifier statistic (`stats.py`), exactly matched configurations (`matched_verifiers.py`), stochastic verifier |
| `error_modes/`, `vf_datasets/`, `models/` | answer parser and taxonomy, seeded addition data with disjoint splits, pinned model loading |
| `training/` | GRPO trainer (TRL 1.17.1) with full verifier logging |
| `experiments/` | census, construct gate, pilot, Gate 5, grid generation, run validation, registered analysis (`analyse_grid.py`), post-registration supplement (`analyse_grid_supplement.py`) |
| `vf_stats/` | registered statistics (`confirmatory.py`), power simulation, predictor comparison |
| `simulations/`, `figures/` | theory and simulation (Gates 1–2); figure scripts, outputs in `figures/out/` with input hashes |
| `configs/` | locks (`locked/`), pilot outputs (`pilot/`), registered grid (`grid/`) |
| `results/` | pilot validation; grid validation, analysis, supplement and per-run records (`grid/run_records/`) |
| `docs/` | plan, decisions, gate reports, pre-registration, Phase 4 closure, reproduction, provenance |
| `paper/` | LaTeX source, generated numbers, compiled PDF |
| `slurm/`, `bin/`, `scripts/` | cluster job scripts, wrappers, manifest tools |
